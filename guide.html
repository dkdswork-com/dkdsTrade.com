Trade Memo Private V10

หลักการ: Journal ใช้งานแบบ local-first ข้อมูลหลักอยู่ใน IndexedDB ของ browser. Google Drive, Gemini และ Excel reader เป็น optional integrations.

1. นำเข้า Order หลายรายการ

ในหน้า Diary กด 📷 อ่านจาก MT5 แล้วเลือกได้หลายภาพเพื่อให้ Gemini อ่าน หรือ Import ไฟล์ CSV/Excel โดยตรวจรายการก่อนบันทึกได้ทุกครั้ง.

2. วันและเวลาเข้า/ออก Order

V10 แสดงวันและเวลาเข้าแยกจากวันและเวลาปิดใน Diary, Summary, หน้าตรวจสอบ CSV/Excel/Gemini และหน้ารายละเอียด Order รูปแบบวันคือ YYYY-MM-DD HH:MM:SS และใช้เวลาไทยหลังปรับ offset แล้ว (ค่าเริ่มต้น +7 ชั่วโมง) จึงเห็นได้ชัดเมื่อถือข้ามวันหรือข้ามหลายวัน.

ตัวอย่าง: opening_time_utc = 2026-09-15T15:05:01 และ closing_time_utc = 2026-09-17T02:10:00 จะปรากฏเป็น เข้า 2026-09-15 22:05:01 และ ออก 2026-09-17 09:10:00. วันที่ปิดอาจอยู่คนละวันกับวันที่เข้า และ Order จะถูกจัดเก็บตามวันปิด/วันลงไดอารี่.

ถ้าภาพ/ไฟล์ไม่มีวันที่จริง ระบบจะแสดง ไม่พบวันที่ในต้นฉบับ สำหรับเวลาเข้า/ออกนั้น แทนการทำให้ดูเหมือนอ่านวันที่ได้. วันลงไดอารี่ยังใช้สำหรับจัดเก็บรายการที่ไม่มีวันที่จากต้นฉบับ.

3. การเรียง Order

Order ในหน้า Diary จะเรียงตามวัน-เวลาเข้าออเดอร์จากเก่า → ใหม่ ไม่ว่าจะเพิ่มพร้อมกันหลายไม้หรือทยอยเพิ่มในภายหลัง.

4. ราคาเข้า/ออกและ Pips

ราคาเข้าและราคาออกถูกตัดทศนิยมที่เกินออก เหลือสูงสุด 3 ตำแหน่ง เช่น 2654.98765 → 2654.987. Diary และ Summary แสดง Δ ราคาและ Pips ตามทิศทาง Buy/Sell. ค่า Pip เริ่มต้นเป็นแนวทางและปรับแยก Symbol ได้จาก Settings.

5. MFE และ MAE คืออะไร?

MFE (Maximum Favorable Excursion) คือระยะที่ราคาวิ่งไปทางกำไรมากที่สุดระหว่างถือ Order ก่อนปิดจริง ใช้ประเมินว่าราคาวิ่งไปไกลกว่าจุดปิดมากเพียงใด (potential profit ที่เคยมีแต่ไม่ได้ปิดรับทั้งหมด). MAE (Maximum Adverse Excursion) คือระยะที่ราคาเคลื่อนไหวสวนทางมากที่สุดระหว่างถือ Order ใช้วิเคราะห์ว่าระหว่างทางต้องทนการติดลบ/การย้อนกลับลึกเท่าใด.

ทั้งคู่ต้องใช้ข้อมูลราคา High/Low ในช่วงเวลาเข้า–ออก หรือ Tick data; ราคาเข้า/ออกและ P&L อย่างเดียวไม่พอ. M1 OHLC ให้ผลประมาณตามความละเอียด 1 นาที ส่วน Tick data แม่นยำกว่าและมีขนาดใหญ่กว่า. MFE/MAE วัดสิ่งที่เกิดขึ้นในอดีต ไม่ได้ทำนายว่าจะเกิดซ้ำในอนาคต.

6. วิธีดาวน์โหลดข้อมูลราคาใน MT5 สำหรับ MFE/MAE

  1. เปิด MT5 บน iMac/PC ที่มีบัญชีโบรกเกอร์เดียวกับที่ใช้เทรด.
  2. เปิด Market Watch แล้วคลิกขวาเลือก Symbols.
  3. เลือก Symbol ที่ต้องการ เช่น XAUUSD หรือ XAUUSDc.
  4. เลือกแท็บ Bars แล้วตั้ง Timeframe เป็น M1 จากนั้นกด Request และ Export เพื่อได้ CSV; หรือใช้แท็บ Ticks หากต้องการละเอียดมากขึ้น.
  5. ต้องมีข้อมูลครอบคลุมเวลาตั้งแต่เข้า Order จนถึงเวลาปิด และชื่อ Symbol/เวลาโบรกเกอร์ต้องตรงกับ Order history.

MT5 ระบุว่าประวัติราคาเก็บในรูปแบบ minute bars และสามารถ Request/Export ประวัติ Bars หรือ Ticks เป็น CSV ได้; ข้อมูล Tick มีปริมาณมากและใช้เวลานานกว่า. อ่านรายละเอียดได้ที่ MetaTrader 5 Help: Downloading price history.

สถานะใน V10: V10 แสดงวันที่/เวลาเข้าและออกแล้ว แต่ยังไม่ได้คำนวณ MFE/MAE โดยอัตโนมัติ. ขั้นต่อไปคือให้ TradeMemo รับไฟล์ CSV ที่มี MFE/MAE ที่คำนวณแล้ว หรือเพิ่ม MQL5 exporter สำหรับจับคู่ประวัติ Order กับข้อมูลราคา M1/Ticks แล้วนำผลกลับมา Import.

7. CSV / Excel / Gemini

CSV/Excel รองรับคอลัมน์วันที่แยกและ datetime รวม เช่น opening_time_utc / closing_time_utc. Gemini ถูกกำหนดให้คืน entryDate/exitDate และวันเวลาเต็มจากแถวในภาพ หากอ่านวันที่ไม่เห็นจริง ห้ามเดา.

8. Position เดียวที่แบ่งปิดหลายครั้ง (Partial Close)

V10 รวมรายการปิดย่อยเป็น Position เดียวในหน้า Diary และ Summary หากรายการมี Position ID เดียวกัน หรือมี Ticket, Symbol, ฝั่ง Buy/Sell, วันเวลาเข้า และราคาเข้าเดียวกัน. ใน Diary รายละเอียดจะขยาย/ยุบได้ และแสดงวันเวลาปิดจริง, Lot, ราคาเข้า/ออก, Δ ราคาและ Pips ของแต่ละส่วน, P&L สุทธิ และโน้ตที่บันทึกสำหรับส่วนปิดนั้น. สถิติในกลุ่มจะแสดงค่า Δ ราคา/Pips ที่ดีที่สุด, แย่ที่สุด และเฉลี่ย. ป้าย Overnight แสดงเฉพาะกรณีที่ถือข้ามวัน เพื่อลดข้อความซ้ำในรายการที่เปิดและปิดวันเดียวกัน.

นำเข้าจาก CSV/Excel ได้โดยใช้คอลัมน์ ticket, position_id / Position ID, lots (Lot ที่ปิดในแถวนั้น) และ original_position_size (Lot ตั้งต้นทั้ง Position). หากมี Position ID ให้ใช้ค่านั้นร่วมกันในทุกส่วนปิด; หากไม่มี ให้แน่ใจว่า Ticket และข้อมูลเข้า Position ตรงกัน. ในการเพิ่ม/แก้ไขเอง ให้กรอก Position ID และ Lot เริ่มต้นของ Position เมื่อเป็น partial close. อย่าใส่ Lot เริ่มต้นเท่ากับ Lot ที่ปิดในส่วนย่อย เว้นแต่เป็น Position เต็มจริง.

การคิดสถิติ: P&L รายวันยังรับรู้ตามวันที่ปิดของแต่ละส่วน (partial close) จริง แต่ Win/Loss, Win rate, Profit Factor, Expectancy, R:R และ Max Drawdown นับจากผลรวมของ Position ที่ปิดครบแล้วเป็นหนึ่งไม้ ไม่ใช่นับส่วนปิดย่อยแต่ละแถวแยกกัน. Position ที่ยังปิดไม่ครบหรือไม่มีข้อมูลขนาดตั้งต้นเพียงพอจะไม่รวมในสถิติผลลัพธ์ระดับ Position จนกว่าจะระบุได้ว่าปิดครบ.

หาก CSV/ภาพไม่มี Position ID หรือ Lot เริ่มต้นและ Ticket ไม่ตรงกัน ระบบอาจแยกเป็นหลาย Position. กรณีนั้นให้ตรวจข้อมูลนำเข้าก่อนบันทึกหรือเพิ่มข้อมูล Position ID/Lot เริ่มต้นภายหลัง.

9. Google Drive Sync และข้อมูลเดิม

V10 คงระบบ Google Drive Sync, การแยก Standard/Cent, Gemini, Backup และข้อมูล Order เดิมไว้. การโอนภาพใหม่ใช้การอัปโหลด/ดาวน์โหลดพร้อมกันสูงสุด 3 ไฟล์เพื่อลดเวลาซิงค์ครั้งแรก แต่ยังแสดงข้อผิดพลาดถ้าภาพบางรายการไม่สำเร็จและให้กด Sync ซ้ำได้; ข้อมูล Order หลักยังรวมแล้วอัปโหลดเป็นไฟล์เดียวแบบเดิม. ไม่ต้อง Import Order เก่าซ้ำเพื่อให้วันที่ซึ่งมีอยู่แล้วแสดง. หลังอัปโหลดไฟล์ทั้งหมด ให้ Reload เว็บทั้ง iMac และ iPhone เพื่อให้ Service Worker V10 ถูกโหลด.

10. ความเป็นส่วนตัว

ข้อมูลหลักอยู่ใน IndexedDB ของ browser. CSV/Excel ถูกอ่านใน browser. ภาพจะถูกส่งให้ Gemini เมื่อกดใช้ AI เท่านั้น. อย่าเก็บรหัสผ่าน MT5, private key หรือ seed phrase ในแอป.
